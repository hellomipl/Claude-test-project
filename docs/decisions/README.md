# Architectural Decision Records

Create an ADR when a change makes a significant or hard-to-reverse decision.

Examples that warrant one here:

- Changing what triggers an agent run, or adding/removing a human approval gate
- Changing the branch or merge strategy
- Introducing an application stack, data store or test harness
- Changing an API compatibility policy
- Choosing a security or tenancy boundary

Do not create an ADR for routine implementation detail.

Naming:

```text
ADR-0001-short-title.md
ADR-0002-short-title.md
```

Copy `ADR-TEMPLATE.md`, take the next number, and link the issue.
